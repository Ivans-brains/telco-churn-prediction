# Telco Customer Churn Prediction

## 📌 Описание задачи
Телеком-компания теряет клиентов. Цель проекта — построить модель, которая предсказывает вероятность ухода клиента (Churn), чтобы отдел маркетинга мог вовремя предложить ему удержание.

**Бизнес-ценность:** удержать старого клиента дешевле, чем привлечь нового. Нам важнее найти всех, кто уйдет (высокий **Recall**), даже ценой ложных звонков лояльным клиентам.

## 📊 Данные
Используется датасет [Telco Customer Churn](https://www.kaggle.com/datasets/blastchar/telco-customer-churn). 
- 7043 строки, 21 признак.
- Дисбаланс классов: ~26% ушедших, ~74% оставшихся.

## ⚙️ Что было сделано
1. **EDA и очистка:** преобразован тип `TotalCharges` из строк в числа (заполнение пропусков медианой), удален `customerID`.
2. **Кодирование:** бинарные признаки (`Yes/No`) закодированы через `LabelEncoder`, мультиклассовые — через `One-Hot Encoding` (`get_dummies`).
3. **Масштабирование:** для `LogisticRegression` применен `StandardScaler` к числовым признакам (`tenure`, `MonthlyCharges`, `TotalCharges`). Деревья обучались на сырых данных.
4. **Борьба с дисбалансом:**
   - LR и RF: `class_weight='balanced'`.
   - XGBoost: `scale_pos_weight`.
   - CatBoost: `auto_class_weights='Balanced'`.
5. **Настройка порога:** порог предсказания понижен с `0.5` до `0.3`, чтобы максимизировать Recall (поиск уходящих клиентов).

## 📈 Результаты (при пороге 0.3)
| Модель | Accuracy | Recall | F1-score | ROC-AUC |
| :--- | :--- | :--- | :--- | :--- |
| **Logistic Regression** | 0.6507 | **0.9287** | 0.5854 | 0.8444 |
| **Random Forest** | 0.6947 | 0.8681 | 0.6016 | 0.8385 |
| **CatBoost** | 0.6758 | 0.9055 | 0.5973 | **0.8461** |
| **XGBoost** | 0.6758 | 0.8877 | 0.5925 | 0.8355 |
| **LightGBM** | 0.6995 | 0.8556 | **0.6019** | 0.8302 |

## 💡 Главный вывод (Бизнес-компромисс)
Лучший Recall показывает **LogisticRegression (92.8%)**. Однако при этом Precision падает: модель будет часто ошибочно предсказывать уход лояльным клиентам (ложные тревоги). 

Для бизнеса выбор модели — это компромисс: 
- Взять **LR**: поймаем 93% уходящих, но менеджеры потратят время на звонки лояльным клиентам.
- Взять **CatBoost**: поймаем 90% уходящих при лучшем ROC-AUC, что дает более честное ранжирование клиентов по вероятности ухода.

Финальный выбор порога и модели должен согласовываться с отделом маркетинга, исходя из стоимости звонка и ценности удержанного клиента.
